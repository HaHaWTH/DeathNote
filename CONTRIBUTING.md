# Contributing to DeathNote

Include the client version, master data version and resource version with protocol reports. A report for a failing RPC should include its method path, gRPC status and the client action that triggered it. Use test accounts and share request summaries with credentials and personal data removed.

Keep protocol definitions and server behaviour in sync. Verify changed RPCs against a temporary instance and use synthetic accounts for inventory, reward, login and settlement checks. Describe how to reproduce the check in the change proposal.

Write project documentation in English. Keep examples in the documentation and use descriptive names in source files.
